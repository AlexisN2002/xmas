# Changes in xmas, newest first

## Version 2

What a user of xmas can do now that they could not before:

- Give a system a budget: `MAS(..., budget=Budget(max_cost_usd=2.0, max_wall_s=600, max_calls=40))`. A call starts only while the run is below every limit, so a budget of 0 spends nothing. When a limit is reached the run ends with status `over_budget` instead of an exception, and the message names the limit, the amount and the call it refused. A box spends from the budget of the system around it.
- Read what every call cost: each record carries latency, cost in USD, the provider's token counts (cached and reasoning tokens included where the provider reports them), the finish reason, the error kind and the model that actually served the call, next to its binding name. Cost is never guessed as zero: it comes from the response when the gateway reports it, else from a price per model you pass to the client (`APILLM(price=TokenPrice(...))`), else it is unknown, and a sum with one unknown part is unknown. A cost budget refuses the next call while a cost is unknown and has no price.
- Keep the work of a failed run: the trace returns every record that finished before the failure, a run status (`ok`, `failed`, `over_budget`) and a typed error kind (money, rate limited, outage, timeout, length cut, bad format, refusal, budget, unknown). When one item of a batch fails, the other items keep their results and are not run again.
- Run plain code as a node: `MAS(..., steps=[Step("count", uses="count_words")])` runs a function, or an MCP tool, between agents without a model call. The same function can also be a tool an agent calls.
- Pass structured data: every value is text or JSON, or a list of them at any depth (`list of text`, `list of list of json`). A JSON value or a list reaches a prompt as one line of JSON, a function gets the real object, not a string, and a list may be read where JSON is wanted. Every item of a list is checked, and an item may be `null`.
- Ask an agent for JSON with a fixed shape: `Agent(..., output_type="json", schema={"fits": {"type": "bool"}})`. The prompt ends with format lines no optimizer can drop; an answer that does not fit gets exactly one retry, then the run stops with a `bad_format` error.
- Let a node decide where the run goes: `when` (taken if a condition on its fresh answer holds), `else`, and `switch` (the edge whose case equals a field, for example `verdict.action`). Conditions are a small checked language, never code: fields, comparisons, `and`, `or`, `not`, `exists`, `len`, `visits`, `cost`, `elapsed`, and functions you register.
- Loop with a cap: a `while` edge goes back until its target ran `max_visits` times; then the record is marked capped and the `else` edge takes over.
- Route a failure by its kind: `on error: [timeout, outage]` (or `any`) sends the run to a fallback node and keeps the failed record, with the cost of every call the visit paid. A budget stop is never caught. A node whose only edges are `on error` edges ends the run when it succeeds.
- Fan in safely: a node fed by several edges is a merge, which runs on whichever edge arrives, or a join, which waits for one edge of each group and runs once per pass. The check refuses anything else and names the clashing edges. A value with several writers that are not alternatives needs `state: {value: {merge: last}}`, so the latest write wins.
- Put a whole system inside another as one node, a box, with `Box("shorten", inner, reads={...}, writes={...})`. The trace keeps the box's records nested, and `Trace.walk()` names the path to each one.
- Mark nodes `frozen`: no optimizer changes their prompt, model, wiring or edges. Topology search works on version 2 systems and keeps steps, boxes, frozen nodes, conditions and chains as they are.
- Read health signals on every trace: retried, bad format, routed errors, failed items, empty, stuck, unfilled placeholders, leaked markup, unusually long or short answers, items over their budget, how often each loop ran and whether it hit its cap, how much of each budget limit was used, and per chain how many items ran, failed and cost. They are for information only; a healthy run shows none.
- Find every wiring mistake when the system is built, listed together: a value read before anything writes it, two writers of one value, a placeholder the agent does not read, a JSON value sent where a function wants text, an unknown function, a condition on a field the answer form does not have.
- Run some nodes once per item of a list with a `for each` chain: `MAS(..., each={"writer": ForEach("page", "plan.slides", at_once=4, key="id"), "render": "page in plan.slides"})`, or `for each: page in plan.slides` in a spec. Items run in parallel, `at_once` caps how many at a time, and every record names its item and key. Outside the chain each value it writes is a list in item order. A failed item leaves `None` in those lists and the other items go on; a budget stop or an unrouted out-of-money error still ends the run. A `while` edge inside a chain repairs one item and caps per item.
- Start a run from several named values and read several outputs: `mas.run_state({"plan": ..., "house": ...})` checks every input before any call and lists every problem at once, and `MAS(..., outputs={"deck": "json", "notes": "text"})` puts each output's final value in `Trace.outputs`, with `Trace.output` the first. With declared outputs, several branches may end a run. The trace carries a `run_id` and the system's `graph_id`.
- Watch a run as it goes: `run_state(..., on_event=...)` hears each visit's and each item's start and end, with the node, the item and a status. A listener that raises is warned about once and gets no more events.
- Retry a node on a passing failure: `retry: {outage: 1}` runs an agent or step again after an outage, a timeout or a rate limit. One record keeps the number of retries and the cost of every attempt.
- Read two values no node writes: `error`, the failure an `on error` edge routed to the node, and `run`, what the run has spent so far.
- Fill a placeholder from a value of another name with a read map, `Agent(..., inputs={"slide": "page"})` or `reads: {slide: page}`, and let agents share one prompt with `prompt: judge`; an optimizer changes a shared prompt for all of them.
- Cap the model calls in flight across a run with `Budget(max_parallel_calls=4)`, and flag an item that costs too much with `item_budget={"cost_usd": 0.05}`, which never stops it.
- Write all of this in a spec file of version 2 (`version: 2`), and draw or name a system from `MAS.describe()`, plain data with an `id` that does not change when only a prompt does.

What changed in the format: a version 2 spec has `inputs`, `outputs`, `agents`, `steps` and `boxes` with typed `reads` and `writes`, `for each` and `retry` on nodes, `schema` and a shared `prompt` on agents, reads as a list or a map, `edges` that may carry `{when: ...}`, `{when: ..., max_visits: n}`, `{switch: ..., case: ...}`, `else` or `{on error: [...]}`, and the sections `state`, `frozen`, `health` (length factor, minimum samples, extra leak patterns), `callables` and `prompts`. Models appear by name only, and keys never appear. Trace and record dictionaries keep their keys in their order and add a key only when it is set.

What stays the same: version 1 files load, run and save exactly as before, and so do their optimizers. The request a one-agent system sends is checked byte for byte, as is the bare-prompt encoding of a single agent. promptolution's optimizers run unmodified, and the public calls `run`, `run_batch`, `predict`, `copy`, `to_yaml` and `from_yaml` keep their behaviour. Every tool call runs, since a tool call need not be idempotent. A failed plain call's error reads `RuntimeError: LLM batch failed: ...` as before; a version 2 failure reads `Type: message`. A version 1 trace gains a `health` key only when a signal fires. Three differences on xmas's own model class and tool agents: a permanent provider error (bad request, key or money refused) is sent once instead of six times, and `APILLM(full_response=False)` keeps the earlier behaviour for plain agents; a tool turn sends a permanent error once either way; and a tool agent whose last turn is cut by `max_tokens` or refused before it wrote anything fails with `length_cut` or `refusal`, as a plain agent does, instead of answering `""`.

Planned next, not in the code yet:

- Save a version 2 system as a `.mas` bundle, a folder with one file per part. Until then `to_yaml` refuses one and `to_dict` gives its spec.
- `verify`, which checks a saved bundle on three levels: checksums of every file and the code it points to; a dry check of the wiring, the prompts and the model names, with no model call; and the warm-up examples carried in the bundle, run under a small budget. A failure warns.
- `first of`, which races branches and keeps the first good result.
- Images, audio, documents, tables and files as values, and `run_state` over them.
- People as nodes of a system.
- A Stop that ends a running system and keeps every record so far.
- Learning from human picks.
